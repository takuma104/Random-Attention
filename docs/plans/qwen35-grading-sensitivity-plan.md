# Legacy graderの表記差: 感度分析方針

2026-09-11、主評価100/500問完了時に12件のfalse negativeを確認した後の**事後的**追加。元の事前登録や主スコアを変更するものではない。

## 固定する原則

- 生成、元grader、元回答JSONには手を加えない。生成の再実行も不要。
- 主報告の数値は「固定したlegacy graderによるスコア」と明示。別versionの表記差レビューを副次的な感度分析として併記し、片方だけで有利な結論を選ばない。
- 500問×全5条件×全2反復へ同一ルールを適用する。cap例の扱い、boxed抽出位置、問題cluster、paired seedは変えない。
- boxedがない回答を推論本文から救済しない。EOSを要求する副指標も引き続き別に示す。

## 表記の扱い

1. 自然言語の単語/語句全体を包むLaTeX text wrapper（例: `east`と`\text{east}`）は、内容の完全一致を確かめる。一般の数式内の文字や単位を無差別に削除しない。
2. 問題が実根/解の列挙を求める場合に限り、単一のplus/minus表記と明示的な2根を比較する。通常のordered tupleをunordered setへ変換しない。各根の式としての一致を確認する。
3. 進数のsubscriptは無条件に削除しない。問題がその進数での答えを要求し、回答本文も同じ進数を明示しているか文脈レビューする。`2516`という十進整数と`2516_8`は一般には等しくない。
4. 未知のケースは推測で正解にせず、未解決として件数と影響を記録する。

## レビューと再現性

- 既に見た100問の例は開示済み（`qwen35-main32k-grading-review-100.json`）。そこをblind review済みとは称さない。
- 残りの候補レビューではcondition名を隠したpacketを作り、question/gold/boxed/final textのみで判断し、その後にconditionへ戻す。
- 自動採点を通過した回答からも、固定hashで100例を抽出してfalse positiveがないか確認する。全件を完全に人手検証したとは主張しない。
- 各補正は元record SHA256、規則、根拠、旧値/新値をsidecarに保存し、raw JSONは不変にする。
- 確認できた表記差を補正した場合とlegacyの場合で、全セル・対応付き差・同じbootstrap CIを併記する。補正後の解析は事後的な感度分析と明示する。
- 必要なCPU依存関係は主評価の環境と分離する。実行中のvenvやfrozen sourceを更新しない。
